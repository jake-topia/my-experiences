# Mind the Fruit Plan

the game just have a start screen similar to RLGL and Last One Standing where everyone waits for players and the host can start the game when enough players are in the game (in this case 2 players needed).

Once the game starts the 1500 x 1500 area of the game is transformed into an arena where tiles are placed evenly around similar to tiptoe. At the center of the area there is a big rect (3-4x the size of the tiles) in which a fruit sprite will be displayed. For now we let this rect cover viable tiles that we spread evenly around. This rect should use the displayRect sprite I am adding. For 8 seconds, the display / big rect in the middle should say "memorize the fruits!". For this duration each tile will display the sprite for a random fruit (for now since we have no fruit sprites you'll use the basicText sprite to put one word fruits - for these text sprites and any text sprites we want to keep centered on a tile, we should set the sprites containerWidth to the width of the tile and set its position X and Y equal to the tiles and use textAlign "center"). After this 8 seconds, the sprites on the tiles disappear, and the display rect in the middle now shows the sprite of which fruit is safe, underneath it it says Safe checkmark in green text. Players then have 6 seconds to go to where they remember this fruit was on a tile. At the end of 6 seconds the non-correct tiles will disappear and the correct tiles fruit sprites will reappear. This logic is important: if a player was NOT colliding with a correct tile, they'll be moved to a 100 x 100 bottom left corner with text above the corner that says You Got Out! but this text should be purely client-sided and should not appear to still in game players. The tile generation should go around this area meaning the generation should probably avoid creating tiles in all corners to create an even an interesting shape of tiles. If 1 player remains at any moment, announce the winner and move back to waiting. When that happens at the end of a round resolution, use the winner phase in place of the normal resolve phase: keep the correct tiles shown, replace the center fruit / Safe checkmark messaging with centered winner text, tint the winning player green, and then count down back to the lobby. If everyone gets out in a round and there is no clear winner, replay that same round number/config instead of advancing to the next harder round. If more than 1 remains. move onto the next round. Tiptoe uses a custom player hitbox for their game but for ours we can do the simple onCollisionStart and onCollisionStop to keep track of if a player is on a correct tile. Remember dealing with stateManager based stuff - if I tell you the variable is of X type, we can take it in as X type and we do not need to do any sort of type checking or on "Variable as any" stuff.

The pool of fruits available to be chosen at random increase per round with 3 fruits on the 1st round, 4 on the 2nd, 4 on the 3rd, 5 on the 4th, 6 on the 5th, 7 on the 6th and 8 on the 7th. 8 will be the max for the following rounds if there are still players alive. The time to memorize fruits will decrease by 0.5 seconds for rounds 8+ however. The pool of fruits for the early rounds should be the same but become more random as rounds go on. for example rounds 1, 2, and 3 should all have strawberry, banana, grape, apple, but then the subsequent rounds add the remaining fruits on the fruit list at random so maybe round 5 can add a guava or blueberry or pineapple, etc.
